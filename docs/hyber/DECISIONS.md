## 3. Developer calls (owner delegated these)

| Topic | Decision |
|---|---|
| URL scheme | `/` landing · `/login` · `/app` (resolver) · `/platform/*` (Super Admin) · `/{branchId}/signup` · `/{branchId}/admin/*` (round 2: `schedule/{day|week|month}/{date}`, `students[/:id[/:tab]]`, `settings/{section}` incl. `settings/audit-log`; older addresses redirect) · `/{branchId}/tutor/*` · `/{branchId}/parent/*` · `/{branchId}/student/*` · `/{branchId}/kiosk`. Branch IDs are slugs and may not use reserved words (`app`, `login`, `platform`, `admin`, `api`, `assets`, …). |
| Sign-in | Google sign-in goes through the project's default auth domain (`hyber-crm.firebaseapp.com`), the only return address registered on the OAuth client. Using the app's own domain needs its `/__/auth/handler` added to that client in Google Cloud first. After sign-in, `/app` sends the Super Admin to the Platform dashboard (all branches) even when they also belong to a branch; anyone else goes straight to their branch, or picks one if they have several. |
| Tutor access to students (Q21) | The basic student record (name, grade, school, status, subjects, learning notes) holds nothing sensitive, and every staff member can read it; the schedule and session logs need it. Contacts, parents, address, birth date, school login and intake answers live in `students/{id}/private/profile`, **admin-only**. The tutor Students page lists only students the tutor teaches (sessions in the last 90 days or upcoming). |
| Branch public profile | `branches/{b}/public/profile` (name, logo, colors, sign-up enabled) is world-readable, so the sign-up page and the branch picker can show the brand before access exists. |
| Staff record | `staff/{id}.role` mirrors the employee's single role on the member doc (`owner`, `admin`, `tutor`; round 2). Schedule rows = active staff with the `tutor` role. Editing an employee's role updates both docs in one batch. |
| Pay data | Shifts (`clockShifts`) are the only stored worked time. Admin "Time Entries" create, edit and delete shifts (with an optional forced type, e.g. a meeting that is all admin time). Teaching/admin segments are computed by `shared/pay` on demand; locked pay periods store a snapshot. |
| Pay-period lock | `branches/{b}/payroll/state.lockedThrough` (a dateKey). Rules refuse shift writes on or before it. Periods are locked in order. |
| Past-day lock | Sessions carry `dayEndAt` (the next local midnight); rules refuse client writes to sessions whose day has ended. Session-log submission and scheduled jobs run on the server. |
| Kiosk PINs | Hashed on the server, stored where clients can't read them (`branches/{b}/kioskPins/*`), unique per branch, set by an admin through a callable. |
| Notifications | In-app inbox docs (`notifications`) and per-person preferences now; FCM push later with the phone app. Tutors see a bell with the unread count; items link to the post or the schedule week. Items are written only by Cloud Functions with deterministic IDs (a retried trigger can't notify twice). |
| Admin Home | TE's cards minus Diagnostics, fed by live listeners (no 30-second polling). "Missing & Needs Attention" = sessions in the last 14 days whose start passed (plus an optional grace, default 0 as in TE) without a submitted log, unfixed automatic clock-outs (the stored `autoClosed` flag, not a midnight guess), and pending sign-up requests. The sidebar Home badge counts those plus new students to follow up. Clicking an auto clock-out opens the correction dialog. Shortcuts are saved per person and branch in the browser. |
| Announcements | Real routes (`announcements`, `/new`, `/:id`, `/:id/edit`), so posts can be linked. Audience: all tutors or picked people (`audienceType` + `audienceKeys` = member emails), checked by the rules. Categories = the branch defaults (Settings) plus any typed in the editor. Pinned posts float to the top. HTML is sanitized (DOMPurify) on save and on display; images and attachments go to Storage under the post's folder. Read receipts are write-once and only the tutor portal writes them (TE: admins never did). `readCount`/`commentCount` are kept by functions; deleting a post removes its receipts, comments and files. Admins may delete any comment. The read-receipts dialog also lists who hasn't read it yet. |
| Session notifications | TE's decision table (`shared/src/schedule/notify.ts`): "Session Confirmed" for new confirmed sessions; cancellation of a confirmed session and its correction; reassignment (both tutors); no-show, date, time and subject changes (one per update, in that order). Only sessions starting within `notifications.sessionChangeWindowHours` (24) before or after the change notify; pending sessions stay silent, as in TE. Hyber adds "Session Deleted"/"Session Restored" when a confirmed session goes to or comes back from the Trash. Each item obeys the tutor's switch for new sessions, changes or cancellations. |
| Daily jobs | 08:00 UTC: automatic student statuses (TE's rules, 20 idle days → Paused) and each student's next session date; a hand-set status is left alone until an admin clicks "Let Hyber manage it again". 08:30 UTC: inbox items older than `notifications.retentionDays` and trashed sessions older than `trash.retentionDays` are deleted. |
| Installable app | One PWA, "Hyber CRM" (`start_url` `/app`), with a small service worker that only serves the last app shell when offline. The installed icon shows the tutor's unread announcements, like TE's News badge. |
| Parent & student portals | Parent: upcoming sessions for linked children (list or month, 4 weeks at a time, per child) and the progress reports the branch shared, which open the printable report. Student: Home (next session, hours, what's coming up, shared reports), Calendar and My Info (the basic record; contact details stay admin-only). Statuses use family words (Scheduled, Confirmed, Attended, Missed, Canceled); staff notes on sessions are not shown. The branch's contact details (Settings → profile) appear for questions and changes. |
| Sample data | "Add sample data" (Super Admin) runs the `seedDemoData` function: the data set includes submitted logs, counters and other people's comments that clients may not write. |

## 5. Round 3 (owner, 2026-10-01)

The owner's third list (`HyberCRM_Round3_Changes.md`, local): branch tab icons, a new Home, subjects, sessions in conflict, right-click menus, the session log, progress reports and a loading bug. The tab icon and website rows are in §4.

| Topic | Decision |
|---|---|
| Access check | Branch pages decide access only after the account check (Super Admin, memberships) is done; until then a spinner. No member doc means "No access", a paused member "Your access is paused". An e2e check fails if any error or "paused" screen flashes while deep links load in a new tab. |
| Sessions in conflict | A booked session (pending or confirmed, not ended, no submitted log) is **in conflict** when the day is closed, it runs outside that date's hours, its tutor is on hold, finished, paused or removed, the tutor's availability (read through that date's hours) doesn't cover it, the tutor has more students at once than the branch allows, its student is booked elsewhere at the same time, or the student is paused or no longer coming (`shared/src/schedule/conflicts.ts`, computed live, nothing stored). **Admin schedule:** the tutor's row is gray where unavailable with a red "Unavailable · N sessions to move" / "N sessions in conflict" label; each card gets a red dashed border, stripes, a warning badge and a tooltip with the reason; days are widened (closed time hatched) so no session disappears, and closed days with sessions stay in the week. **Resolve** (card right-click, or the edit dialog's red notice): give to another tutor (only tutors free then with a seat), make the tutor available for that time, move, or cancel; status, note and subject can still be changed without moving it. **Tutor:** a banner "N of your sessions are waiting for the admin" and the same marking with "Not confirmed: … Waiting for the admin to move, reassign or cancel it." **Home:** conflicts in the next four weeks come first in the attention list (and the sidebar count). Admins aren't emailed (Home is their inbox). **Families** see nothing: it's a staffing question, and auto-confirm skips conflicted sessions, so they stay Pending. **Warnings before creating one:** availability edits (tutor and admin), Edit day, per-date hours, putting a tutor on hold or finished, pausing a tutor's access, un-canceling; the weekly hours and the students-per-tutor rule say so in their help. |
| Right-click menus | One menu definition per item gives both the right-click menu and, where useful, a "⋯" button (`components/app/ItemMenu.tsx`). Session cards: resolve (when in conflict), status, write or view the log, edit, reassign, copy, duplicate to next week, student profile, Trash; past days and tutors get only the log and student. Also: tutor names, empty time (new session here, paste), day headers, events, and the students, employees, Account, payroll, time entries, session logs, announcements, Trash and Subjects lists. |
| Subjects | Every branch starts with the **default list: 125 subjects in 7 categories** (`shared/src/subjects.ts`, stable IDs from the name), written when the branch is created; the sample data adds "Other" (Homework Help, Study Skills) to show a branch's own additions. Branches edit their copy freely. Existing branches got the missing defaults by name (`scripts/migrate-round3-subjects.ts`); Demo Academy's old sample subjects were mapped onto the default ones. Tutors' subjects stay informational: they never block booking. |
| Session log: the form | Rebuilt with True Education's structure and detail (owner): the same six steps (Prepare, Session Info, Materials, Notes, Evaluation, Review & Submit), fields, required markers, validation order and messages, and TE's wording and placeholders verbatim; field labels and card titles in Hyber's sentence case, step tabs in TE's Title Case. No curriculum browser (owner). **Prepare:** admin note, student strip (school, grade, total hours, status, learning notes, Full profile ↗), the latest parent conference note for the session's tutor when the branch holds conferences (served by `sessionLogContext`; the notes stay admin-only otherwise), "From last session" (same subject by ID, then name, else the newest; empty AI cards hidden) and TE's Recent sessions table (6 per page, ↗ opens the log). **Notes** stack full width at 240 / 240 / 160 / 160 px minimum and grow with the text (owner: taller), with a word count and a soft hint only, no minimum lengths (TE has none); Polish keeps line breaks, can be undone, and never names the AI. Session type, homework status and flag are one-click chips. **Suggestions only:** the last same-subject session type is preselected and tagged, recent topics and materials from that subject, last session's homework, and a flag suggested from the ratings (not selected); notes and ratings are never prefilled. **Drafts** save ~2 s after typing stops, on Next and blur, when the tab is hidden or closed, and at least every `autosaveSeconds`, with "Saving… / Draft saved · time / Couldn’t save" in the footer; drafts hold only the log's own fields (rules) and are mirrored onto the session as `logStatus: 'draft'`. **Submitting** is allowed only once the session has started (it marks attendance, bills hours and makes the time teaching pay); drafts any time. Review lists what's missing with a link to each step. |
| Session log: view, edit and on behalf | A submitted log opens **read-only** (from the schedule, the list and Prepare) and editing is explicit: **Edit log** for admins and, when allowed, its tutor; Cancel while editing returns to the log (confirming unsaved changes), and edits are never autosaved. The view renders from the log's own copy, so tutors can read other tutors' logs when `tutorsSeeAllLogs` is on, and a deleted session's log still opens. It shows a record panel (status, submitted when and by whom and how long after the session ended, entered by admin, last edited and the edit count, billed hours, session type), the attribution banner, TE's AI overview (summary hero, then plan, homework and risk), the session info, the notes with their line breaks, every rating, and for admins the context (admin note at the time, the previous session's plan) and the **History** of submits and edits with what changed. Print, Open in schedule and Close. **On behalf:** admins fill in the same form with TE's purple banner; the log stays credited to the tutor. Attribution is `enteredBy` (the first submit), `lastEditedBy` and the audit `changes[]`: "Entered by admin" only when an admin made the first submit, so an admin's later edit never relabels a tutor's log. |
| Session Log list and logged sessions | TE's texts, sorted by date and start time, with Student, Tutor (admins; tutors who may read all logs), From/To, Status (admins: Submitted, Drafts, Missing) and Flag filters in the URL. **Missing** means a loggable session has **ended** without a submitted log (TE), also in the Add dialog, which preselects the tutor with the most missing logs. Schedule indicators use TE's tooltips per portal ("Please write your session log." for tutors, "Session log missing" for admins), the phone schedule shows them too, and canceled or No Show sessions don't offer a log. A session with a submitted log **stays Present** (app and rules); moving, re-timing, reassigning or re-subjecting it updates its log's copy and billed hours on the server (`onLoggedSessionUpdated`). No delete-log UI. |
